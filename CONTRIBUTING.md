# Contributing to DirectGTM-Labs

DirectGTM-Labs builds evidence-backed Growth and GTM methods, code, experiments
and capability proofs. The first DirectGTM-OS reference use case is career
acquisition; the eight workflow areas are Identify, Research, Detect Signals,
Qualify, Engage, Automate, Measure and Learn.

## Useful contributions

- Reproducible engineering or SQL improvements using synthetic data.
- Corrections supported by primary sources or documented observations.
- Clear bilingual definitions and practical examples.
- Experiments that state their assumptions, metric definitions and limitations.

## Before submitting

Read the project's README and licence. Open an issue before proposing a large
change. Work on a topic branch and submit a pull request to `main`.

Describe the problem, the resulting behaviour and the checks you actually ran.
If a check was not run, say why. Keep roadmap proposals separate from completed
features. Distinguish fact, inference, hypothesis and unknown; an LLM response
alone is not evidence.

For a proof, record the environment, input data, query or code, actual output,
assistance level and remaining verification. Assisted execution is useful and
must not be presented as an independent competence assessment.

Use public, synthetic, or suitably anonymised data. Do not submit client
secrets, private contact lists, raw interview messages, credentials or
unpublished operating knowledge. Gatekeeper-Bypass concerns evidence and
additional legitimate acquisition routes.

## Review and support

The maintainer reviews contributions as capacity permits. The project has no
guaranteed response time. Acceptance does not change the repository's licence;
read the applicable terms before contributing, especially for content projects.

For code problems use the project's issues. For confidential security reports
follow SECURITY.md. For professional enquiries contact contact@mingmingcodes.com.
